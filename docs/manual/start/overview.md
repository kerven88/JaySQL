按模块列出 JaySQL 的能力、典型场景与菜单入口，便于快速定位你需要的功能在哪。

## 功能矩阵

| 模块 | 关键能力 | 典型场景 | 入口 |
| --- | --- | --- | --- |
| 首页 | 实例总览、待办与风险、快捷入口 | 每天上班第一眼 | `/home` |
| AI 助手 | 服务商接入、模型管理、对话与 SQL 建议 | 自然语言转 SQL、优化建议 | `/ai` |
| SQL工作台 | SQL 查询、新建工单、工单列表与详情 | 自助查数、上线变更 | `/sql-workbench` |
| 备份恢复 | 备份任务、备份集、存储目标、数据恢复向导 | 定时备份、误删数据找回 | `/backup` |
| 性能分析 | 性能概览、慢 SQL、负载快照 | 慢查询治理、事故回溯 | `/performance` |
| 监控告警 | 监控大屏、监控明细、告警中心、告警配置、监控配置 | 实时巡检、告警响应 | `/monitor` |
| 安全审计 | 操作日志、策略配置 | 合规检查、事故溯源 | `/audit` |
| 系统管理 | 用户 / 角色 / 权限、数据访问、系统配置 | 开账号、配参数 | `/admin` |
| 文档中心 | 产品文档、AI 文档问答 | 查用法、查排障 | `/docs` |

## 一次典型使用路径

```text
纳管实例（系统管理）
   → 授权研发可查哪些库（数据访问）
   → 研发自助查询 / 提交变更工单（SQL工作台）
   → DBA 审批并执行（工单流程）
   → 定时备份 + 定期演练恢复（备份恢复）
   → 慢了就查慢 SQL（性能分析）
   → 出事先看监控与告警（监控告警）
   → 事后追溯谁改了什么（安全审计）
```

## 权限视角

平台采用**权限点 + 角色 + 数据访问授权**多层控制：前者决定「能不能进这个菜单 / 点这个按钮」，后者决定「能查哪个实例的哪个库表、能查多少行」。

| 层级 | 控制对象 | 示例 |
| --- | --- | --- |
| 功能权限 | 菜单与操作按钮 | `sql.console.access`、`backup.task.manage`、`monitor.view` |
| 数据权限 | 实例 / Schema / 表 / 行数 | 系统管理 → 数据访问，按用户或角色授权 |
| 流程权限 | 工单审批节点 | 审批流中指定用户或角色 |

:::info 关于权限口径
功能权限不足时页面会跳转 403（不是按钮置灰）；数据权限不足时表现为库表列表为空或查询被拒。
:::

## 术语表

阅读文档时会反复出现这些词，先对齐口径：

| 术语 | 含义 |
| --- | --- |
| 实例 | 被管的一个数据库服务（主机 + 端口 + 引擎） |
| 环境 | 实例的分组标签，如生产 / 预发 / 测试 |
| 备份集 | 一次成功备份形成的**可用恢复点**，带业务 ID（`bks-` 前缀） |
| 执行记录 | 备份任务的一次运行，成功且保留后才形成备份集 |
| 存储目标 | 产物存放位置：本地服务器或对象存储 |
| 健康分 | 实例的综合评分，由若干扣分项计算 |
| 预检 | 恢复执行前的只读检查，不写数据、不落库 |
| PLAN / EXECUTE | 恢复的两种模式：演练 / 真正执行 |
