JaySQL 是一套面向数据库运维与研发协作的一体化管理平台，把「查询与变更、备份与恢复、性能与监控、审计与权限」收敛到同一个控制台。

## 它解决什么问题

当数据库实例从几个增长到几十上百个，引擎横跨 MySQL、PostgreSQL、Doris、TiDB、PolarDB、Oracle、OceanBase、ClickHouse 时，常见的痛点是：

- **变更没有闸门**——谁在什么库上执行了什么 SQL，出了事只能翻聊天记录
- **备份各写各的**——crontab + 自研脚本，能不能恢复没人敢打包票
- **问题定位靠运气**——慢 SQL、磁盘、连接数分散在不同工具里，缺少统一视图
- **权限靠人情**——研发要查生产库，给账号还是不给？给了查到什么程度？

JaySQL 的做法是：把上述动作全部**工单化、留痕化、可回放**，并用同一套元数据库把实例、任务、结果、审计串起来。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 统一纳管 | 多引擎实例集中登记，按环境（生产 / 预发 / 测试）与组织分组 |
| SQL 工作台 | 在线查询受数据访问授权约束；变更走工单 + 规范预审 + 审批流 |
| 备份恢复 | 逻辑 / 物理备份、定时计划、保留策略、多存储目标；恢复向导含预检与二次确认 |
| 性能分析 | 慢 SQL 采集与治理、负载快照报告、性能概览 |
| 监控告警 | 资源与数据库指标采集、实例健康分、多级告警与多渠道路由 |
| 安全审计 | 操作留痕（含变更前后的数据快照）、策略配置、数据访问授权 |
| AI 助手 | 接入大模型后提供 SQL 生成、优化建议、慢查询解读 |

## 适合谁

- **DBA**：日常巡检、备份恢复演练、慢 SQL 治理、变更把关
- **研发**：自助查询与提单，不必再找 DBA 要账号
- **运维负责人 / 安全**：看审计、控权限、管合规

## 不是什么

明确边界，避免误用：

- **不是数据库本身**，也不替代数据库自带的高可用方案；它管的是"人和流程"，不是"主从切换"
- **不代持业务数据**：业务数据始终在被管实例与存储目标上，平台只保存元数据、任务记录与审计
- **不是聊天机器人**：AI 助手生成的 SQL 不会自动执行，涉及变更仍须走工单与审批

:::tip 一分钟判断要不要用
如果你需要回答「这个库昨天谁改了什么」「上周的备份能不能恢复」「现在哪个实例最危险」这三个问题中的任意一个，JaySQL 就是为你准备的。
:::
