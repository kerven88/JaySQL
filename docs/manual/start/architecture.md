JaySQL 由「控制台前端 + 服务端 + 元数据库 + 执行节点 + 采集链路 + 存储目标」六部分组成，各层职责清晰、可独立扩容。

## 分层架构

![JaySQL 分层架构](../assets/architecture.svg)

图：从上到下依次为接入层、应用层、数据层、执行与采集层，最底部是被管数据库。

| 层 | 组成 | 说明 |
| --- | --- | --- |
| 接入层 | Web 控制台（Vue3 + Ant Design Vue）、REST API、AI 助手、工单与审批 | 唯一用户入口 |
| 应用层 | Go + Gin + GORM，含工作台 / 工单 / 备份 / 监控 / 性能 / 审计与定时 cron | 业务编排与调度 |
| 数据层 | 元数据库（MySQL）、指标库（Prometheus）、存储目标 | 平台自身数据都在这里 |
| 执行层 | backup-agent + mysqldump / pg_dump / xtrabackup / pgbackrest | 跑在被管主机上 |
| 采集层 | node_exporter + 数据库采集 SQL + 慢日志采集器 | 指标与慢日志来源 |

## 关键组件与职责

| 组件 | 职责 | 说明 |
| --- | --- | --- |
| 服务端 | 业务编排、调度、接口 | 决策层只写库、不发网络请求；耗时动作交给后台 worker 或执行节点 |
| 元数据库 | 平台自身数据 | 实例、工单、备份恢复、告警、审计等；迁移到新环境需清理运行期数据后再启用 |
| backup-agent | 在被管主机上执行备份 | 通过 poll / heartbeat 与服务端通信，超时常见于网络或代理问题 |
| Prometheus | 采集与存储指标 | 跨机抓取需把 `instance` relabel 为实例登记值，否则页面显示无数据 |
| 存储目标 | 存放备份产物 | 本地服务器走 SSH，对象存储走 S3 兼容协议 |

## 部署拓扑（最小可用）

```text
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  浏览器       │─────▶│  服务端       │─────▶│  元数据库     │
└──────────────┘      │  :8083       │      │  MySQL       │
                      └──────┬───────┘      └──────────────┘
                             │
             ┌───────────────┼───────────────┐
             ▼               ▼               ▼
      ┌────────────┐  ┌────────────┐  ┌────────────┐
      │ backup-agent│  │Prometheus  │  │ 存储目标    │
      │（被管主机A）│  │ + exporter │  │ 本地 / OSS │
      └────────────┘  └────────────┘  └────────────┘
```

- **服务端与被管主机之间需要互通**：agent 主动 poll，所以是 agent → 服务端方向建连
- **Prometheus 与被管主机之间需要互通**：Prometheus 主动抓取，方向是 Prometheus → exporter
- 两者网络要求不同，跨机房 / 上云时要分别验证

## 设计约束（改动前请阅读）

这些是写死在架构里的约定，二次开发时不要绕过：

1. **告警决策异步化**——告警判定只落库，实际投递由异步 worker 完成，带退避、限流与熔断
2. **备份产物带 sidecar**——产物同目录写 `metadata.json` 与 `checksums.sha256`，恢复时据此校验
3. **恢复有护栏**——生产环境需四确认、手输特定文本、物理恢复手输 `host:port` 比对，缺一不可执行
4. **状态机必须闭环**——新增中间态前先推演它到所有终态的出口，避免任务永久悬挂
5. **查询与更新同口径**——Service 里 `Where` 查询与 `Where` 更新必须用同一套条件，否则会静默 0 行返回成功

:::warn 一个高频坑
改了配置不生效时，按三段定位：**配置是否落库 → 是否下发到执行节点 → 是否被执行链路真正采用**。
涉及备份执行代码的改动，服务端重启还不够，执行节点上的 backup-agent 也要更新。
:::
