查询与变更的统一入口：查询受数据访问授权约束，变更走工单流程并在执行前做规范预审。

## SQL 查询

- 只能看到**被授权的实例与库表**；未授权的库表不出现在下拉里
- 查询结果有**行数上限**与**超时时间**，由系统参数控制，防止大查询拖垮实例
- 查询记录进入审计（含语句、耗时、行数），可用 `request_id` 串联

:::warn 查数与导出的区别
页面内查询受行数限制；导出同样受限且会留痕，**不要把它当成绕开审批的通道**。
:::

## 工单流程

| 阶段 | 说明 | 产物 |
| --- | --- | --- |
| 提交 | 选择实例与库、填写 SQL、选择执行时间 | 工单记录 |
| 预审 | 按开发 / 生产规范检查（如无 WHERE 的 UPDATE、大表 DDL） | 预审结果与风险等级 |
| 审批 | 按审批流流转，可多节点 | 审批记录 |
| 执行 | 按任务拆分执行，支持定时与失败中断 | 任务与执行日志 |
| 回滚 | 必要时生成回滚语句 | 回滚 SQL |

### 任务状态怎么看

工单拆成多条任务执行，详情页能看到每条任务的状态与日志：

- **PENDING**——等待执行（含定时未到点）
- **EXECUTING**——执行中
- **SUCCESS / FAILED**——终态

:::info 工单一直卡在 EXECUTING
先定位卡在哪条任务，再看原因，常见三类：

1. **Binlog 回滚 SQL 被阻塞 / 连接风暴**——目标库锁等待
2. **服务端被重启杀掉**——任务没有收尾，需要人工干预状态
3. **目标库主机不可达**——网络或实例故障

处理前先确认不是"还在正常跑大事务"：看目标库的 `processlist` 与执行耗时。
:::

## SQL 规范

规则分**开发规范**与**生产规范**两套，级别决定是提示还是拦截。规则项可在系统配置中调整参数与级别。

- MySQL 规则：由审核器按语句类型逐条匹配
- PostgreSQL 规则：连库失败时**静默跳过**（这是设计行为，不是漏检）

:::info 规则不生效或页面看不到
按顺序查三件事：

1. 规则所属**规范集**与实例是否正确绑定
2. 环境是开发还是生产（两套规则不同）
3. 跨环境迁移时**规则 ID 可能不一致**——这是最高频的坑，比对两个环境的规则记录
   :::

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 看不到某个库 | 数据访问授权未包含该 Schema | 系统管理 → 数据访问，按用户或角色授权 |
| 执行卡住不动 | 锁等待 / 主机不可达 / 服务端重启 | 见上文「工单一直卡在 EXECUTING」 |
| 规范预审没拦住 | 规则未绑定或连库失败静默跳过 | 检查规则绑定与目标库连通性 |
| 导出被拒 | 超出行数限制或无导出权限 | 拆分查询或申请授权 |
