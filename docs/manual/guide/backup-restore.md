定时把数据搬到可靠的存储目标，并在需要时按可预期的方式还原回来。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 备份任务 | 定义备份什么（实例 / 库表）、多久一次、保留多久 |
| 执行记录 | 任务的一次运行，含状态、产物路径、日志路径 |
| 备份集 | 一次成功备份形成的**可用恢复点**，带业务 ID（`bks-` 前缀） |
| 存储目标 | 产物存放位置：本地服务器或对象存储 |
| 恢复点 | 可用于恢复的备份集 / 执行记录 |

:::info 备份集 ID 与主键不是一回事
界面上看到的 `bks-` 开头的是**业务 ID**，数据库主键是数字 `id`。排查时对不上多半是搞混了这两个。
:::

## 备份类型

| 类型 | 工具 | 适用 | 限制 |
| --- | --- | --- | --- |
| 逻辑备份 | `mysqldump` / `pg_dump` | 中小库、单表恢复、跨版本迁移 | 大库慢、恢复耗时 |
| 物理备份 | `xtrabackup`（MySQL）/ `pgbackrest`（PG） | 大库、快速恢复 | 要求**同构环境**，版本与配置需匹配 |

### 产物完整性

每次备份会在产物同目录写 `metadata.json` 与 `checksums.sha256`，恢复前据此校验：

- `backup_type` 只取 `logical` / `physical`，备份层级放在 `extra.backup_level`
- 校验和格式为 `<sha256><两个空格><文件名>`，且必须包含主产物
- sidecar 写入失败**只告警不阻断**备份

:::warn 恢复前的同构校验
物理恢复会校验目标实例与备份来源是否同构（版本、引擎、平台）。
MySQL 物理恢复只支持恢复到**已有实例**，不支持新建实例。
:::

## 存储目标

| 类型 | 前置条件 | 地址形态 |
| --- | --- | --- |
| 本地服务器 | 完成 **SSH 指纹确认** | `192.168.1.99:/backup/ds-xxx/bk-xxx/000001-1/backup.zip` |
| 阿里云 OSS / 腾讯云 COS / 华为云 OBS / MinIO | 通过**连通测试**（put / head / list / delete） | `oss-cn-hangzhou.aliyuncs.com:/bucket/ds-xxx/...` |

页面展示的「产物路径 / 日志路径」为 **地址 + 路径** 的完整形态，复制按钮取到的也是完整路径。

:::tip 选不了存储目标？
- 本地服务器：提示「SSH 指纹未确认」→ 到存储目标管理页完成指纹确认
- 对象存储：提示「未通过连通测试」→ 先做一次连通测试

注意这两类目标的校验项是**不同类型**的，不要拿 SSH 指纹的要求去要求对象存储。
:::

## 恢复向导

唯一入口：**备份恢复 → 数据恢复 → 新建恢复**。三步：

1. **选择恢复点**——按备份集或执行记录挑选
2. **配置目标**——选择目标实例与策略：结构冲突如何处理（跳过 / 中止）、数据如何处理（跳过 / 中止 / 清空后导入）、恢复范围（全量 / 自定义）、库名映射
3. **确认执行**——先看**预检结果**，再选择 PLAN（只演练）或 EXECUTE（真正执行）

### 预检是什么

预检是**无副作用**的只读检查：不落库、不写数据、强制按 PLAN 逻辑推演。

返回结构：

```json
{
  "summary": "...",
  "items": [{ "phase": "...", "item_key": "...", "label": "...", "status": "...", "level": "...", "message": "..." }],
  "resolved": {},
  "plan": {},
  "risk_level": "MEDIUM"
}
```

:::danger 三道护栏（不可绕过）
1. 生产环境需勾选**四项确认**
2. 手输指定**确认文本**
3. MySQL 物理恢复需手输 `host:port` 与目标实例比对

任一项不满足，执行会被拒绝。这三项是防止误操作的最小集合，不要为了省事去掉。
:::

## 排查手册

| 现象 | 定位方向 |
| --- | --- |
| 任务一直不执行 | 检查节点 agent 是否在线（poll / heartbeat 日志）、任务计划与状态 |
| 产物路径显示为空 | 任务未成功完成，或产物未回传；看执行记录日志 |
| 选不了对象存储目标 | 该目标未通过连通测试 |
| 压缩/并行数改了不生效 | 三段定位：是否落库 → 是否下发执行节点 → agent 是否新版本 |
| 恢复卡在某个阶段 | 进入恢复详情看阶段日志；**物理恢复的底层工具输出在目标主机上**，服务端只有回传段落 |
| 任务停在「待执行」不动 | 逻辑侧存在幽灵任务判定（无 agent 认领且长时间静默），可删除后重跑；物理侧落库即起协程，重跑请新建记录 |

## Amazon S3 与 S3 兼容备份目标

新增存储目标时可选择“Amazon S3 / MinIO / S3 兼容服务”，填写 Endpoint、Region、Bucket 和 AccessKey / SecretKey。
AWS 的 Endpoint 使用 Bucket 所在区域的服务地址（不含 Bucket 和对象路径），Region 与 Bucket 一致，Path-Style 默认关闭。
MinIO 使用服务端配置的 Region，IP/本地端点通常需要开启 Path-Style。
密钥加密保存，编辑留空表示不修改。执行备份的节点也必须能访问该端点。

测试连接会检查桶访问、列举和临时对象写入/删除；备份账号还需具有分片上传、读取及清理权限。
预检不会创建 Bucket，需提前建好。保存后在备份任务中选用该目标即可，现有 MinIO 配置继续有效。
当前使用 AccessKey / SecretKey，不包含 STS 临时凭据或 IAM Role 自动发现；S3 目标并不代表新增 Redis 备份引擎。
