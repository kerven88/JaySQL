## 监控明细

- **实例画像**：版本、规格、运行时长等；字段可能显示为不可用并附原因（采集失败或引擎不支持），这不是页面 bug
- **指标分组**：资源（CPU / 内存 / 磁盘 / IO / 网络）与数据库指标分组展示
- **健康分**：按扣分项计算，可查看扣分明细，等级可自定义

:::warn 指标显示「无数据 / no_data」
最常见原因是 Prometheus 里**没有该实例对应的时间序列**。按顺序查：

1. **目标主机上 node_exporter 是否在运行**——`systemctl status node_exporter`
2. **Prometheus 的 target 是否 up**——管理页看 targets，或 `curl http://prom:9090/api/v1/targets`
3. **抓取 job 是否把 `instance` relabel 成了实例登记值**——
   平台用 `instance=~"^<hostname>(?::[0-9]+)?$"` 匹配，**跨机抓取必须 relabel**，否则指标全 no_data

补充：一个 node_exporter 可以被**多套 Prometheus 同时抓取**（无状态，标签由各自 relabel 决定），
跨机房场景下可以两端各起一套 Prometheus 抓同一个 exporter。
:::

## 告警中心

| 概念 | 说明 |
| --- | --- |
| 等级 | P0 ~ P3，影响展示顺序与升级策略 |
| 状态 | 触发中 / 已恢复 / 已忽略；已忽略可带过期时间 |
| 告警内容 | 规则命中后的具体描述（含指标值与阈值） |
| 升级 | 未及时响应的告警按升级策略通知下一级 |

## 告警配置

- **告警策略 / 规则**：绑定指标与阈值、作用范围、生效时段
- **通知渠道**：钉钉、飞书、企业微信、Telegram、邮件等；密钥加密存储，**留空表示不修改**
- **投递机制**：判定只落库，投递由后台 worker 异步完成，带**退避（10s→1m→5m→30m）、分钟级限流、连续 5 次失败熔断**

:::tip 收不到告警？按三段排查
1. **告警是否真的产生**——告警中心有没有这条事件
2. **通知任务是否创建**——看通知任务的状态与渠道
3. **渠道本身是否可达**——注意 **HTTP 200 + 业务错误码 ≠ 成功**，要看响应体里的业务码
   :::

### Telegram 与自定义消息正文

在通知渠道中选择 Telegram，填写 Bot Token、Chat ID，可选群话题 ID 和 Bot API 地址。
Token 加密存储，编辑时保持掩码或留空表示不修改。机器人需先在私聊中启动，或加入群/频道并获得发送权限。
保存后使用“测试”验证渠道；随后在通知策略中选择该渠道并配置生效范围。

展开渠道编辑窗口的“告警消息模板（Markdown）”，点击变量按钮插入 `{{instance_name}}`、
`{{metric_name}}`、`{{observed_value}}`、`{{threshold}}`、`{{title}}`、`{{state}}`、`{{url}}` 等字段。
“填入示例”可生成起点；“恢复默认正文”清空自定义内容。未知变量不能保存。
选择触发、恢复或认领阶段后点击“预览”，可以检查格式及纯文本；预览只使用样例数据，不发送消息。

Telegram 支持适配后的标题、加粗、斜体、列表、链接与代码，不透传 HTML，不渲染图片及表格；
超过单条 4096 字符上限会报错。不同渠道对 Markdown 的支持程度不同，以实际测试结果为准。
自定义正文在入队时生成快照，修改模板不影响已入队任务；聚合通知保留系统多告警摘要。

## 监控配置

- 采集策略模板与采集项（指标字典是元数据， seeded 初始化，不要删）
- Prometheus 接入：填写地址与抓取配置
- 采集周期、告警周期建议由**统一参数**驱动，避免多处硬编码导致口径不一致
