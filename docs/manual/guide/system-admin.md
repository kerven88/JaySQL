平台自身的配置中心：谁能用什么、能看什么数据，以及各模块运行参数。

## 权限管理

- **用户管理**：创建与禁用账号、重置密码、绑定角色与组织
- **角色管理**：角色是**权限点的集合**，建议按职责建角色（如「研发只读」「DBA 全量」），不要按人建
- **组织**：用于数据范围的粗粒度隔离

:::tip 权限点命名规律
形如 `<模块>.<对象>.<动作>`：`sql.console.access`、`backup.task.manage`、`monitor.view`、
`system.user.view`。看到菜单报 403 时，先确认角色里有没有对应的 view 权限点。
:::

## 数据访问

按主体（用户 / 角色）授权到「实例 → Schema → 表」级别，并可限制**返回行数**与**允许的语句类型**。

:::info 授权不生效的常见原因
1. 授权对象是**角色**，但用户没加入该角色
2. 授权在了**错误的环境 / 实例**上（生产库和测试库长得很像）
3. 页面缓存了旧的库表列表——重新进入页面即可

注意：`insight_das_operations` 是"允许执行的语句类型"**字典表**，不是操作日志，别看名字就误判。
:::

## 系统配置

| 配置项 | 影响 |
| --- | --- |
| AI 能力 | 服务商、模型、调用参数（详见 [AI 助手](./ai-assistant.md)） |
| 采集周期 / 告警周期 | 监控与告警的节奏，建议统一由参数驱动，避免多处硬编码 |
| 慢日志阈值 | 慢 SQL 的入库标准 |
| SQL 规范 | 预审规则与级别（开发 / 生产两套） |
| 健康分设置 | 等级与扣分项 |
| 环境管理 | 实例分组标签（生产 / 预发 / 测试） |

## 实例管理

在这里登记被管实例：主机、端口、引擎、账号密码、所属环境与组织。

- 保存后做一次**连通性测试**，失败时看错误信息是网络不通还是账号权限不足
- 密码等敏感字段加密存储，编辑时留空表示不修改
- 删除实例前先确认没有关联的备份任务与监控配置，否则会产生孤儿记录

:::warn 改了配置不生效？三段定位
1. **配置是否落库**——直接查库确认字段值
2. **是否下发到执行节点**——agent 有没有拉到最新配置
3. **是否被执行链路真正采用**——代码里有没有别处硬编码覆盖了它

涉及**备份执行**代码的改动（executor、物理备份、sidecar），服务端重启还不够，
执行节点上的 backup-agent 也要更新；只改监控模块则不需要重发 agent。
:::

## 迁移到新环境

把已有库迁到全新环境时，需要清理运行期积累的业务数据后再启用：

- 清理：数据源实例、备份与恢复记录、工单数据、监控运行态数据
- **保留**：监控元数据（指标字典、采集模板、采集策略模板、告警模板、健康分设置）、
  SQL 规范与规则、权限与角色、用户与组织、系统参数
- 全部用可回滚的 `DELETE`，按模块开事务，大表分批执行

:::danger 两个易误删的元数据
- `insight_das_operations` —— 语句类型字典表，**不是**操作日志
- `insight_monitor_alert_rules` —— 是**配置**不是运行态，通常可选择保留（但其 `scope_value` 可能绑着旧实例 ID）
  :::

## Redis 实例登记

实例管理的数据库类型支持 Redis，默认端口 6379。无认证时账号、密码均可留空；
仅密码认证时不填用户名，ACL 认证时填写对应用户。TLS 开启后使用系统信任证书并校验主机名。
编辑时留空保留已保存的密码，也可以勾选“清除已保存密码”连接无密码服务。
测试连接与后台探活仅使用 AUTH / PING；Redis 不同步 SQL 元数据；查询工作台提供只读 Key 浏览，不提供 Redis 备份引擎。
